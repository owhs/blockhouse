## Findings

**F1 · 2/9 · blocker · both · `#/settings`, on arrival, nothing touched** The sticky bar at the bottom reads "You have unsaved changes · Discard · Save changes" on every settings group of both sites, on a freshly loaded page. `settings.js:778/802` correctly does `bar.hidden = true`, but `studio.css:1208 .set-savebar { display: flex }` has higher specificity than the UA `[hidden]` rule, so the attribute never hides anything — verified: `hiddenAttr:true, computedDisplay:"flex"`. The persona is told, permanently and on every visit, that they have unsaved work. Add `.set-savebar[hidden] { display: none }` (or a global `[hidden] { display: none !important }` — it is the only element in the studio currently affected).

**F2 · 9/4 · major · both · `#/users` → Extra access → rail click** Opened the "Extra access — test" dialog, then navigated (`#/e/d-helmsdale`, `#/settings`). The modal and its backdrop are still there, over an unrelated screen, with a Save button that belongs to a person you are no longer looking at. Escape closes it; navigation does not. `ui.js:170 dialog()` calls `showModal()` and never closes on route change — `main.js:336` already does `addEventListener('hashchange', closeRibbon)`; dialogs need the same.

**F3 · 1/9 · major · both · topbar → site name → Switch site** The switcher lists "Strongman Lifts — http://localhost:57001" and "Strongman Lifts — http://localhost:57002". Two identical labels, neither marked as the one you are in, and the addresses are internal ports that match neither the studio (8792/8793) nor the public addresses the dashboards show (`strongmanlifts.co.uk` / `www.strongmanlifts.co.uk`). The owner cannot tell which site they are about to open. `main.js:540 openSiteSwitcher()` and the `/projects` payload (`p.label`, `p.current`, `p.url`).

**F4 · 11 · major · both · editor** Two preview modes still coexist. strongman `d-home`, `d-helmsdale` and automatic `p-tower-parking-system` render a fixed `1024 px` iframe scaled with `transform: scale()` — 62% on strongman, 85% on automatic, so the same option shows the page at two sizes. automatic `d-about` renders `width: 100%` with no transform and no scale strip at all — the site's ~870 px layout at 1:1. On top of that, "Desktop" is a 1024 px viewport: the owner never sees the desktop layout their visitors get, and at 62% the body copy is unreadable. `editor.js` preview sizing / `.preview-frame-holder`.

**F5 · 1/12 · major · both · editor, any document** Entering the editor collapses the rail to 54 px of icons (`nav.side`, `.side-label` measures 0 px wide). Purpose is carried only by `title` and a CSS `.tip` — hover-only, which the rubric rules out. The Dashboard icon's tooltip is also the description ("Everything that needs you today"), not its name. `nav.js` / `studio.css` collapsed rail.

**F6 · 4/10 · major · both · editor → Page tab → Appearance → Page template** The help line is now plain ("Which page layout to use. Leave as Default unless a designer told you otherwise."), but the options are raw template filenames: `—`, `Default (product)`, `404`, `faqs`, `home`, `list`, `page`, `product`, `project`, `range`. Same class of defect as round-1 finding 5, in the field list the owner uses most. Concept schema / `fields.js` template picker.

**F7 · 7 · major · both · `#/seo`** Header reads "3 pages are fine · 35 need attention" (automatic is comparable). The `suggestion:` prefix and the uncapped lists are gone — good — but 32 of the 35 are the single row "No short description for search results", and the home page `/` is listed as "Very little writing on this page (0 words)" although it is a full page of blocks. The word counter evidently does not read block content, so the flagship page is reported as empty. `seo.js` audit — word count over rendered block text, and rank/summarise so a site missing descriptions does not read as a broken site.

**F8 · 12/8 · minor · both · `#/audit`** The three filter dropdowns (person, kind, date range) have no `<label>`, no `aria-label` and no visible caption — a screen reader announces three unnamed combo boxes, and sighted users infer the purpose from whichever option happens to be selected. `audit.js` filter row.

**F9 · 3 · minor · both · `#/media`** Assets is the only rail page with no ? button; every other screen (including Template code) has one. Also: the SEO sheet says "Fix the 33 page(s) still missing a description" — a code placeholder in owner-facing copy — and the Settings sheet is titled "Help with Site" while the rail, the topbar and the hash all say Settings. `help.js` topic map.

**F10 · 12 · minor · both · editor → Add block → Escape** The picker closes, but `document.activeElement` is `<body>` — the "Add block" button that opened it is not refocused, so keyboard users are thrown to the top of the document. The `dialog()` helper does restore focus correctly (verified on Publish), so the picker is the odd one out. `editor.js` picker open/close.

**F11 · 4 · minor · both · editor → outline** Rows put the content preview and the block type on one line and clip with an ellipsis, so the type — the part that tells you what the row *is* — is what disappears: "Common questions we get aske FAQ grid", "The Helmsdale … Rich ...". Three of seven rows clip on `d-home` at the default 240 px outline; on `d-helmsdale`, eighteen consecutive "Rich text" rows all clip. Put the type on its own muted line, or drop it when the preview already fills the row.

**F12 · 6/1 · minor · both · `#/c/all`, `#/c/page`** Content rows are `<tr>` elements with a `<span class="cell-title">`; there is no `<a href="#/e/…">`. Round-1 finding 19 was fixed for the rail but not here, so a document still cannot be ⌘-clicked into a new tab or copied as a link — exactly the action an owner takes when sending a page to a colleague. `views.js` list renderer.

**F13 · 2 · minor · both · `#/settings` → search "logo" → click a result** Clicking "Picture used when a link is shared" switches to the Site group and clears the box, but nothing scrolls, nothing flashes and focus stays on `<body>`; the field sat at y≈830 of a 900 px viewport, i.e. at the very bottom edge. On a longer group it will be off screen. (Round 1 could not test this; it is testable now and it does not land.) `settings.js paintMain()` — the `requestAnimationFrame`-scheduled scroll/flash.

**F14 · 5 · minor · both · editor → Block → Layout → Width** Widths now render distinctly (strongman hero: 608 / 710 / 961 / 985 / 1009 px; Section inner container: 832 / 913 / 945 / 977 / 1009), so round-1 finding 3 is resolved. What remains: "Template default" is a sixth option that always duplicates one of the other five — on a Section it is identical to Normal (913 px), on the hero identical to Edge to edge (1009 px) — so two of six choices do the same thing and which two depends on the block. Say which one it follows, e.g. "Template default (Normal)". Also "Page width" and "Edge to edge" differ by 24 px, which is ~15 px at 62% preview scale. `src/render/layout.ts`, `src/render/native-blocks.ts:51`.

**F15 · 5/8/2 · minor · both · wording** Four leftovers: block picker, Footer column — "Drop three of these into the **footer.columns slot**"; People → Extra access — "Use every **plugin**" (the rail and every other screen call them Apps) and "Sync to **git** & manage backups"; Deploy → Export site files — "Writes every page into the **dist folder**", outside the "Technical details (for developers)" disclosure; rich-text toolbar — "Show markdown source"/"MD". Block manifests, `src/core/permissions.ts`, `deploy.js`.

**F16 · 12 · minor · both · ⌘K** The palette renders `role="listbox"` with exactly one active row (good), but the input is a plain `<input aria-label="Search the studio">` with no `role="combobox"`, no `aria-controls` and no `aria-activedescendant`, so a screen-reader user hears nothing as they arrow through results. `quick.js`.
