## Findings

**R12-1 · 11, 10, 1 and 6 · major · both sites · `#/`, `#/c/product`, any page, at 390×844 (and at any width below ~477 px)** Set the viewport to 390×844, dispatch `resize`, reload. The studio shell is **477 px wide inside a 390 px window** and `document.documentElement.scrollWidth` is **390** — so 87 px of every page is off screen with nothing to scroll to it. Measured on strongman `#/`: `.app` 390, `.view` 477, `.main` 477 (its own `overflow-x: auto` scrolls the content inside a viewport that is itself 87 px too wide), `.topbar` 477. Casualties on the dashboard: "View site" is cut mid-word, "＋ New" runs `324→423`, every "Continue editing" row title and every status chip is sliced. On `#/c/product` the table header runs to x 709 and the Status column can never be fully seen. Screenshot attached in-session confirms all of it. The cause is one track: `studio.css:889` sets `.app, .app.layout-ribbon { grid-template-columns: 1fr }` in the `max-width: 860px` block, and `1fr` is `minmax(auto, 1fr)` — the column takes its **min-content** from `.topbar` (`studio.css:129`, a flex row with the default `min-width: auto`), whose five children measure 29 + 76 + 105 + 37 + 159 px plus gaps ≈ 477. Below 477 px the shell therefore stops fitting. It is exactly the R10-3 / R11-1 defect one level up, in the app shell rather than a panel. Fix: `grid-template-columns: minmax(0, 1fr)` on that rule, `min-width: 0` on `.topbar`, and let `.top-site`/`.top-end` shrink (`min-width: 0` plus ellipsis on the site name) so the topbar's own children give way instead of the page. Verified clean at 480 px and 767 px — only below ~477 does it break. *The mobile drawer itself is correct and is not part of this finding:* `.app.nav-open .side` slides in over a 390 px scrim, focus moves into it (first item "Content"), it is never clipped, real Escape closes it and returns focus to the "Menu" button.

The accessible name is complete, so a screen-reader user is fine, but the sighted site owner has to guess or widen nothing — the panel is fixed-width while the window has 100+ px spare. The other five rows ("All", "Drafts", "Waiting for review", "Published", "Scheduled") fit exactly. Either widen the filter panel by ~1 rem, wrap the label to two lines the way `.help-nav .row-label` now does (`studio.css:2016`), or shorten it to "Changed since publishing". Built in the list view's filter panel (`views.js`, the `.row-item` + `.row-label` + `.count` rows).
