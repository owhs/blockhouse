# Round 2 — package B: block manifests, option labels, concept help

Owner files: `src/render/native-blocks.ts`, `src/render/blocks-extra.ts`, every `../templates/*/blocks/*.json`, `../sites/strongman/plugins/strongman/index.ts` (copy the finished file to `../.uxcritic/strongman/plugins/strongman/index.ts` too), `../sites/strongman/_concepts/*.json` and `../sites/automatic/site/concepts/*.json` (copy each to the matching `../.uxcritic/<site>/…` path), `src/assets/admin/fields.js` (select option label fallback only), `../templates/*/assets/base.css` only if item 4 applies. Read `docs/ux-overhaul/01-workplan.md` rules first, then findings 4, 5, 16 in `docs/ux-overhaul/03-critic-round1.md`.

Audience for every string: the person who runs a lift-installation business.

1. **Block descriptions** (finding 4). Every block in the catalogue gets a `description` of one plain sentence that says what it is for and when to use it. Rewrite the developer ones ("Wrapper with width, background and anchor controls" → "A band across the page. Give it a background and put other blocks inside."; "WYSIWYG text, stored as markdown" → "Paragraphs, lists and links — most of your writing goes here."; "Responsive grid — each child block becomes a cell" → "Side-by-side columns. Put a block in each."; "Inline vector art — theme-aware via currentColor" → "A simple drawing or icon that matches your colours."; "Accessible accordion + automatic FAQ structured data" → "Questions that open to show the answer. Search engines understand it too."; "YouTube/Vimeo with a privacy-friendly click-to-load facade" → "A YouTube or Vimeo video that only loads when someone presses play."). Add descriptions to every block that has none (Hero, Divider, Spacer, Heading, Quote, Image, Gallery, Button, and all template/site-plugin blocks).
2. **Option labels** (finding 5). Every `select` field in every block manifest must have a `label` for each option — no raw keys. Section: background `none` → "None", `subtle` → "Soft tint", `accent` → "Brand colour", `contrast` → "Dark"; padding `normal` → "Normal", `compact` → "Tight", `spacious` → "Roomy", `none` → "None". Do the same for every other select (image size, heading level/align, gallery ratio/fit, photo-row columns/fit, etc.). In `fields.js`, when an option has no label, fall back to a capitalised, de-hyphenated value — so a future manifest omission still reads as a word.
3. **Field help strings** (finding 16). Grep every `help:` / `"help":` across native blocks, template block JSON and the two sites' concept files. Rewrite any that mention files, paths, Liquid, `.liquid`, `{{`, "template", "markdown", "structured data", "currentColor", "facade". "Anchor id — Link to this section with #anchor" → "A short name so links can jump straight to this section (letters and dashes)". Concept field "Page template — Add pages/<name>.liquid…" → "Which page layout to use. Leave as Default unless a designer told you otherwise."
4. **Width classes that measure the same**: package A will report any template where two of narrow/normal/wide/page/full measure identically at a 1024px frame. If `../templates/strongman/assets/base.css` or another template's `.bh-w-*` rules make two values identical at 1024px (e.g. wide = page because the grid's outer tracks collapse), adjust so all five are distinct at ≥ 1024px and degrade sensibly below. Check aurora and strongman at least.
