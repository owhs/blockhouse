Read `docs/ux-overhaul/01-workplan.md` rules first, then findings 6, 7, 8, 9, 13 (rail part), 15, 17, 19 in `docs/ux-overhaul/03-critic-round1.md`.

1. **Navigation preview must never navigate** (finding 6). The iframe at `/?__menudraft=…` follows real links. Inject the same guard the editor bridge uses: in `src/assets/blockhouse/runtime.js` (small out-of-scope edit allowed) when `data-bh-preview="menu"`, intercept every `click` on `a[href]` (capture phase, `preventDefault`) and, if the link is a nav item with `data-nav-id`, post `{ blockhouse: 'menuselect', id }` to the parent; `menus.js` listens and selects that item in the tree. Nothing else in the frame may navigate or submit.
2. **Apps in plain English** (finding 7). Rewrite every plugin `description` (one sentence about what the owner gets: "Contact and quote forms. Submissions are kept here and can be emailed to you.") and every capability label so "What it can do" reads as sentences an owner understands ("Add pages to your website", "Store its own records", "Send emails on your behalf", "Run things when something happens on the site"). Codes stay out of sight unless "Limit what it may do (advanced)" is open.
3. **Activity** (finding 8). Default range: "Last 30 days" if there is anything in it, otherwise "All time" automatically, with the sub-line counting what is shown ("Showing 1 thing that happened" / "Nothing has happened in the last 30 days"). Fix plural grammar.
4. **SEO** (finding 9). Drop the "suggestion:" prefix. Rank issues: errors, then warnings; suggestions are hidden behind "Show suggestions" per row. Summary counts only pages with errors/warnings as "need attention"; pages with suggestions only count as fine. Use one name everywhere: "focus keyword" (match the editor). Check `seo-analyze.ts` labels for developer words and rewrite.
5. **Settings search** (finding 15). Stop hand-maintaining rows: build `SETTINGS_ROWS` at runtime from the settings groups' field definitions (settings.js already has per-section field arrays — export a `settingsIndex()` from settings.js that returns `{ group, key, label, help }` for every field; `catalog.js` consumes it). Add synonyms on the fields that need them (logo → share image/site name; cookie → consent app; robots → sitemap/search engines). "No setting matches that" gains a line "Try Apps for cookies and forms, or Design for colours."
6. **People → Extra access** (finding 17): plain label only; the code appears in a muted `badge-code` inside a "Show codes" toggle at the top of the dialog (off by default).
7. **Rail links** (finding 19): rail items become `<a href="#/…">` styled as now, so middle-click and copy-link work; keep the click handler for the mobile drawer close. Fallback icon initials (finding 13): render inside `aria-hidden` and never as part of the accessible name ("laLifts").
