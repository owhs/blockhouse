## Findings

**R1 · 4/9/10 · blocker · both · editor, any document, viewport wider than 1400px** Opened `#/e/d-about` on automatic with `localStorage` cleared, clicked the toolbar's **Outline** button. `aria-pressed` flips to `true`, the `.closed` class is removed — and the panel stays 1px wide: `grid-template-columns: 1px 1035px 336px`. It never opens. Clicking again on a document whose stored preference was "open" leaves it stuck at 240px with the class `outline closed`, i.e. open when it says closed. Reproduced on both sites, on every document, with real clicks and after a hard reload. Cause: `studio.css:725 .outline { width: var(--outline-w); transition: width … }` sits in an **`auto`** grid track (`studio.css:723`). Transitioning `width` inside an `auto` track is circular — the track sizes from the animated width and the animated width resolves against the track — so the transition never completes (`el.getAnimations()` reports `width` `playState:"running"` indefinitely). Below 1400px the outline is `position: fixed` and animates `translate` instead, which is why the drawer at 1024×768 works perfectly. Net effect at the rubric's own test width: the outline defaults closed (`editor.js:584 disclosure('outline', false)`) and the persona has **no way to see the list of blocks on the page**. Animate a `--outline-w` custom property, or give the track a fixed `15rem`/`0` and transition `grid-template-columns` on `.editor`.

**R2 · 12 · major · both · editor → Page tab** 10 of the 11 controls in the inspector have neither an associated `<label>` nor `aria-label`: Slug, Publish at, Model name, Strapline, Range, Card summary, Page template, Visible to… The markup is `<label><span>Slug</span><span class="help">…</span></label><select>` — the label is a **sibling** of the control, with no `for`/`id` pair and no wrapping, so `el.labels.length === 0`. A screen reader announces an unnamed edit box on the field the owner uses most. Settings gets this right, so it is `fields.js`'s `.field` builder only — wrap the control in the `<label>` or emit `for`/`id`.

**R3 · 4/3 · major · both · editor → Page tab → Publishing** The first field on the tab is **"Slug"**, helped by "The last part of the address. Old slugs redirect automatically." That is a developer's word twice in two lines, in the most-visited panel. The same tab's "Who can see this page" says "Install the **Members plugin**" — the rail, `#/plugins` and every other screen call them Apps, and round 2 flagged the identical wording under People. Call it "Address on the site" (or "Page address") and "the Members app". `fields.js` / the concept schema's publishing section.

**R4 · 1 · major · both · topbar → site name → Your sites** The dialog now shows "Strongman Lifts (strongman) — strongmanlifts.co.uk" and "Strongman Lifts (automatic) — www.strongmanlifts.co.uk", so the raw ports are gone. But **neither row is the current one**: both render as `a.row-item` with "Open its studio", and the "You are here" branch in `main.js:559` never runs. `GET /api/projects` returns `current:false` on both — `src/server/api.ts:224 current: p2.dir === current` compares a registry path against `env.projectDir` and the two never match (verified in the live payload). So the owner sees two rows with the same name, disambiguated only by a parenthesised folder key that means nothing to them, and no indication of which studio they are standing in. Compare resolved/normalised paths, and drop the folder key in favour of "You are here".
