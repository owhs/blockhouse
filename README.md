# Blockhouse

**A modular, self-hostable, git-friendly site engine & lightweight app platform.** Content lives as flat JSON you can diff and PR; a professional block-based studio sits on top; the output is an ultra-light, modern site — served live (Bun, Node, or Cloudflare Workers) or exported as plain static files. Agents can drive it over MCP.

Zero runtime dependencies. The router, Liquid-compatible templating, and markdown are small vendored modules built on web standards — the whole engine runs anywhere `fetch(Request) → Response` exists.

**New in 1.3 — the ecosystem round:** the "turn it off and the link stays" class of bug is gone: the **Features switchboard is now enforced end-to-end** — flip RSS (or the sitemap) off and blockhouse 404s the endpoint, drops the `<link rel=alternate>`, hides matching menu items and unwraps stray content links, site-wide, on every template (verified per-toggle). The mysterious footer content has a home: **Site → Header & footer** edits the template *slots* (announcement bar, after-nav, pre-footer, footer links) as blocks with a live preview, and the editor's "where is this configured?" chooser now points at it — plus a Features jump for feed/sitemap links. Templates get a real **IDE**: syntax highlighting, liquid **intellisense** (tags, filters, variables from your actual concepts, partial/menu/slot names, CSS `var(--…)` completion), colour swatches you can click, ⇧⌥F **beautify**, snippets, a cross-reference panel (who includes this file, which slots/menus/regions it renders) and a **live preview of unsaved edits** rendered through an ephemeral resolver overlay. Themes and plugins become an **ecosystem**: install either as a zip **package** with per-file SHA-256 checksums, optional **Ed25519 signatures** verified against your pinned trusted issuers, licence keys stored on install and one-click re-verification; site-local plugins load from `<project>/plugins/` through the same permission gates. Two heavyweight new plugins: **Drive** — a client portal of member-group-gated document areas with self-serve access requests (role + company captured), magic-link sign-in, per-file download tracking and an activity feed; and **Commerce** — carts priced server-side against your Data tables (or a product concept), stock decrement with oversell guards, orders with status workflows and `commerce.order.*` events for automations, Stripe Checkout or manual/invoice payment. Plus: **markdown sync** (point it at an Obsidian-style folder or zip; frontmatter → fields, body → blocks, idempotent re-syncs), five **mail providers** (console/Resend/SendGrid/Postmark/MailChannels/webhook) with a save-and-test button, automations get **variable chips** (click `{{event.x}}` from the real payload into any step), the Plugins screen becomes a searchable card ecosystem, and a **security round**: rename the studio path, **staging protection** (site hidden from anonymous visitors while the studio stays reachable), safe **password reset** (login-page flow + `blockhouse user:reset`), an opt-out **error log** with a studio viewer, an outside-in **self-probe** for exposed sensitive paths with firewall/Cloudflare advice, and new doctor checks (dev-mode-on-public-URL and friends). FAQ/testimonial/timeline blocks are properly centred in every template, and `blockhouse init` sites render on first run.

**New in 1.2 — the control round:** a **template code editor** under Site → Templates: the whole theme (layout, page templates, partials, blocks, CSS) in a grouped file tree with a gutter editor, ⌘S, and every save written as a *site override* — the built-in file is never touched and Revert is one click; three new page templates (**landing**, **deck** — a scroll-snap presentation, **product** — cover hero) join the pickers in the editor's Page tab and in content-type defaults. **Settings** is rebuilt as a grouped panel (General / Features / Brand / Appearance / URLs / Images / Mail / Custom code / System pages / Plugin settings / Build & export / Interface / Security) with a **Features switchboard** — prefetch, view transitions, visitor theme toggle, RSS, sitemap, analytics beacon, OpenSearch — one toggle each, off means nothing ships to the page; plugins add their own settings sections through a new `ctx.settingsSection()` hook (the consent plugin uses it). **Deploy targets**: save named staging/production targets (export / webhook / owner-only command) with **AES-GCM-encrypted credentials**, per-target minimum role, one-click Test, "Deploy staging" (drafts included, separate folder) vs "Deploy live" with confirmation and a run log. A **consent/GDPR plugin**: an honest banner (Decline as prominent as Accept), a manage panel, a preference-centre block for your privacy page, and hard gating of the analytics beacon until the analytics category is granted. In the editor: **focused mode** (hide the site chrome and edit just the content), a preview that **never navigates away** — clicking any non-content element instead opens a permission-checked "**where is this configured?**" chooser that jumps to the exact menu / template file / Design / settings section, and desktop previews that render at real width and scale down so a narrow pane never shows you the mobile layout. Menus gain explicit ▲▼ ordering and per-item **member-group visibility**; content lists gain **CSV export/import** (rows become drafts); fields gain **autocomplete** (`a|b|c` presets, or live values from other content/tables); the data studio gains search, column sorting, CSV download and cleaner key management; analytics gains 7/30/90-day ranges, avg/best-day cards and CSV export; and a **site switcher** in the top bar hops between every registered project (`blockhouse sites add|list|remove`). Plus a real bug hunt: the admin shell no longer double-boots (a versioned-vs-bare module URL split that double-mounted every view), select fields accept pipe-string options, day-precision dates render properly, and `blockhouse init` ships with the home page already published so a fresh site renders on first run.

**New in 1.1 — the studio round:** the icon rail is now a real **sidebar** — grouped, labelled, collapsible (⌘B) — so nothing needs hover-archaeology. **Content types** get a full manager: create products/projects/docs/anything from presets, build their field schemas visually, and watch them appear in the sidebar (custom types were always the engine's core; now they're two clicks). Menus get a **catalogue mega layout** — the full-screen pattern of category tabs → item list → detail pane with CTA — and the menu editor is rebuilt around a **live preview** that renders your draft on the real site (desktop-scaled, mobile toggle, auto-opens the panel you're editing) with an inline inspector instead of dialogs. A new **Design** view previews template cards and injects hue/intensity/radius into the live site as you drag — save when it looks right. **Automations** gain a step builder with per-action forms, an event picker with sample payloads, a **dry-run** that shows every interpolated value without side effects, and a one-click **test run**. **Integrations** gain a per-action live test bench and **custom connectors** built in the studio (URL/header/body templates + auth applied for you) that hot-register as automation actions. Site search now offers engine choices (built-in index, DuckDuckGo/Google site-search, custom URL) plus an **OpenSearch** description so browsers can register your site. Users get invite flows with generated credentials, per-user extra access, last sign-in and role explainers. And `blockhouse init` now scaffolds a page that already looks designed. Plus a studio-wide fix: dialog titles and centering (a real bug — every dialog had lost its header).

**New in 1.0:** website **members** (magic-link or password sign-in, groups, an account portal, and per-page gating enforced in the router *and* excluded from exports, sitemaps, feeds and search), an **integrations** layer with a connector contract that carries OAuth2/refresh/token storage for you (Gmail + Drive, Xero, Zapier, generic REST), an **asset manager** with folders, tags, search, focal points and a non-destructive image-processing wizard, **dynamic help** written from your actual site rather than a generic manual, a **Deploy** view backed by `blockhouse doctor` (runtime, config layers, secrets, security posture, plugin grants, deploy readiness) and `blockhouse budget` (per-page weight against a budget you can fail CI on), `blockhouse deploy:init` presets for Docker/systemd/Caddy/nginx/Cloudflare/Pages/GitHub Actions, **layered configuration** (`site.json` → `site.<env>.json` → `.blockhouse/local.json` → `BLOCKHOUSE_*`), full **URL control** (directory/extension/bare, flat or patterned, mirrors, aliases, shortlinks), **system pages** (build your 404 and maintenance screen out of blocks), **maintenance mode** with a real `Retry-After`, **single-scheme sites** that preview correctly, per-role **module hiding**, and security hardening throughout (CSP modes, HSTS, admin IP allowlist, login throttling, audit log). Two more templates — **Atelier** (square, orange, oversized display) and **Console** (compact docs/SaaS) — join Aurora and Ledger, alongside ~14 new blocks and three new authoring skills.

```
bun install            # optional: sharp (image variants) + dev tooling
bun src/cli/index.ts seed --dir sites/demo     # or: blockhouse seed
bun src/cli/index.ts dev  --dir sites/demo     # or: blockhouse dev
# site   → http://localhost:8787/
# studio → http://localhost:8787/admin/   (first visit creates the owner account)
```

On Node: `node --import tsx src/cli/index.ts dev --dir sites/demo` (installs `tsx` from devDependencies). Bun runs the TypeScript directly.

## Layout

```
sites/<yours>/
  site/site.json          site config, theme tokens, plugin approvals   ← commit
  site/concepts/*.json    content types                                 ← commit
  site/content/**         working copies (drafts)                       ← commit
  site/content/.published publish snapshots (what the live site serves) ← commit
  site/menus|forms|automations|data|newsletter/…  gittable JSON         ← commit
  site/site.<env>.json    per-environment overrides (staging/production)     ← commit
  site/overrides/         header/footer/CSS/block overrides, layered over the template
  media/                  originals (+ _var/ derivatives, rebuildable)
  .blockhouse/secure.db         users, sessions, submissions                       ← gitignored
  .blockhouse/secret            cookie signing key (or set BLOCKHOUSE_SECRET)            ← gitignored
  .blockhouse/local.json        machine-local config overrides                     ← gitignored
```

Everything content-shaped is pretty-printed JSON — reviews are pull requests, rollbacks are `git revert`. Only credentials and user-submitted data live in the secure store (SQLite locally, D1 on Workers, with a JSON fallback).

## CLI

`blockhouse init <name>` · `blockhouse dev` · `blockhouse serve` · `blockhouse export [--stage]` · `blockhouse seed` · `blockhouse check` (validate content) · `blockhouse doctor [--env production] [--target …] [--deep] [--json]` (diagnose everything) · `blockhouse budget [--fail]` (page weight) · `blockhouse deploy:init <target>` (deployment files) · `blockhouse mcp` (agent server) · `blockhouse user:add --email --password --role` · `blockhouse publish:due` (cron-friendly scheduled publishing)

### Configuration layers

```
DEFAULT_CONFIG → site/site.json → site/site.<BLOCKHOUSE_ENV>.json → .blockhouse/local.json → BLOCKHOUSE_* vars
```

Commit the first three; `.blockhouse/local.json` is gitignored for machine-local tweaks; environment variables win, which is what containers and CI want. `blockhouse doctor` prints which layers are in play so a surprising value is always traceable.

## Skills (AI-assisted authoring)

`skills/` contains seven SKILL.md guides an agent can load to help a user:
`blockhouse-site-editing` (content, menus, SEO), `blockhouse-template-authoring` (a theme from a description, tweaks, or an existing site), `blockhouse-block-from-example` (HTML/image/link → editable block), `blockhouse-plugin-dev` (build or extend plugins), `blockhouse-design-system` (tokens, palettes, typography, brand variables), `blockhouse-data-apps` (tables, calculated fields, workflows, reports), `blockhouse-connector-authoring` (add a third-party service), and `blockhouse-deploy-ops` (ship, harden and operate). Pair them with `blockhouse mcp` so the agent operates the site through validated tools.
